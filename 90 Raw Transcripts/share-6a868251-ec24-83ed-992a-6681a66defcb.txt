I learned five main things from Matt Pocock’s skills repo:

1. **Make agents prove reality before reasoning.**  
   For bugs: first create a test/command that reliably reproduces the exact problem. Then diagnose. This is probably the strongest idea in the repo.

2. **Keep agent instructions small and live.**  
   `AGENTS.md` should contain things an agent cannot easily rediscover. Don’t copy commands, paths, config, or other facts that can be read directly from the repo because those copies go stale.

3. **Give agents outcomes, not step-by-step recipes.**  
   A good task says:
   - what is wrong now
   - what should happen
   - acceptance criteria
   - what is out of scope  
   Then the agent explores the current code itself.

4. **Design around testable interfaces, not lots of little abstractions.**  
   He strongly favors “deep modules”: small interfaces hiding substantial complexity. Fewer seams, fewer mocks, tests through real behavior.

5. **His human-interaction philosophy is not a good fit for us.**  
   He deliberately uses lots of user questioning and confirmation. Someone even reported getting 200 questions, and he chose not to impose a limit. I would **not** copy that part.

### Bottom line

The useful thing is **not installing his whole workflow**.

The useful thing is stealing a few principles:

**prove first → keep instructions lean → give agents clear acceptance criteria → test real behavior → avoid unnecessary architecture → let agents work autonomously.**
