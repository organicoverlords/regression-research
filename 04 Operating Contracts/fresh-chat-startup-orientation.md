# Fresh-chat startup orientation

The Vault is canonical for behavior, policy, and memory. Acquire complete behavior once through the configured Vault-primary / Library-fallback delivery route. Do not run both routes when one has already succeeded.

Fresh-chat startup is **behavior delivery -> relevant context -> response**. Bind greetings, shorthand, `go`, `continue`, status questions, and other short prompts to the inherited mission instead of asking the operator to restate known context.

Recent memory, Stack Atlas, and live-state inspection are conditional. Read recent Vault titles only when durable context is needed to resolve the mission or ambiguity. Use Atlas only when dependency, identity, recovery, or blast-radius information matters. Fetch live repo/coordinator/worker/CI/runtime state only when the requested answer or mutation depends on current state. There is no mandatory fleet scan before a greeting, simple question, or small status-independent edit.

Tool discovery is bounded: reuse loaded function schemas; if a required function is missing, discover the narrowest specific function/query available. Do not enumerate an entire connector unless broad capability discovery is genuinely required.

For worker-status questions, current execution evidence remains required; claims, leases, schedules, checkpoints, and old snapshots do not prove activity.

Post-compaction rehydration restores behavior only. It does not rerun fresh-session context, Atlas, memory, or live-orientation work unless the current task independently needs those sources.
