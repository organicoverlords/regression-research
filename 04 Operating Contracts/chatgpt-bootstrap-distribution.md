# ChatGPT bootstrap distribution

The canonical ChatGPT behavioral semantics live in the Vault memory authority layer and are compiled by `build_behavior_bootstrap()`. Library is a distribution transport only. It must never become an independently edited behavior constitution.

The generated distribution artifact is `/Agent Bootstrap/chatgpt-bootstrap.json`. Its producer is `python tools/chatgpt_bootstrap_artifact.py render`. The artifact contains the complete current behavior bootstrap plus a bounded `recent_memory_glance` of at most 20 eligible non-superseded Vault entries (id/timestamp/title/kind/scope/authority), together with byte count and SHA-256 provenance for the canonical behavior bank and authority registry. It contains no full incident bodies, project-history dump, conversation archive, repo history, or live status.

Publication is two-phase. Render the artifact from the intended Vault revision, publish those exact bytes to the Library path, then obtain the published copy and run `python tools/chatgpt_bootstrap_artifact.py verify <copy>`. Do not replace a previously verified Library snapshot until byte-for-byte verification returns `PROVEN`. A publisher or deployment adapter may automate the transport, but it must not rewrite, normalize, summarize, or otherwise synthesize the payload.

Live promotion begins only from a landed Vault revision. Before changing the live Library path, capture a restorable before snapshot of the existing Library file plus the current Personal Instructions and any product UI state needed to distinguish delivery from behavior. Change one live variable at a time: publish only the generated Library artifact, and do not simultaneously edit Personal Instructions, built-in Memory, scheduler state, or coordinator state.

After publication, retrieve the live Library copy and require byte-exact `PROVEN` verification before any acceptance canary. Then run a same-model fresh-chat instruction-delivery canary using `tests/fixtures/instruction-delivery-canary.json` or an equivalent replay that preserves its classifications. Record the published byte count and SHA-256, fresh-chat/model boundary, whether the marker was present in the configured UI, whether effective instruction context was observable, and whether the expected behavior occurred. Delivery failure, delivered-but-not-followed behavior, invalid setup, ambiguity, or any byte mismatch remain distinct outcomes; do not collapse them into one assistant failure claim.

If publication or the canary is invalid, mismatched, or cannot be classified with adequate evidence, do not promote the new snapshot. Restore the previous Library bytes and any live UI state changed for the test, then leave the product-boundary result unresolved. A successful canary proves only that this published artifact was delivered and followed on the tested product path; it does not make Library a semantic authority.

Fresh ChatGPT sessions prefer a compatible local execution route to `python C:\Users\Lauri\Desktop\vault\tools\memory_bank.py bootstrap`. The generated Library artifact is the fallback when local execution is unavailable or the exact command still fails after its bounded retry. A Library consumer accepts the fallback only when the complete generated artifact is returned and `payload.contract.complete_behavior_semantics` is true, then uses `payload` exactly as the bootstrap result.

The artifact is not live orientation. Fresh startup consumes behavior first, then the bounded recent-memory glance, and only then performs the `fresh_session_startup` live-state scan before the first substantive response. Current user instruction and verified current state remain stronger than historical or distributed context.

If both local bootstrap and the generated Library fallback fail, continue from current instructions, applicable already-present policy, and verified live state. Persistent-context loss is a continuity degradation, not a task-level stop condition and not permission to debug the memory system instead of the inherited task.

Legacy `/Agent Bootstrap/agents.md`, `/Agent Bootstrap/chatgpt-memory-seed.md`, tracked old seed files, built-in ChatGPT Memory, and cached/paraphrased copies are historical/recovery evidence only. They are not fallback behavioral authorities for this contract.
